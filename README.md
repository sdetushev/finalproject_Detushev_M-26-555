# ValutaTrade Hub — валютный кошелёк

Консольное приложение на Python для симуляции торговли валютами и управления виртуальным портфелем.

Проект разработан в рамках итоговой работы по Python. Приложение поддерживает регистрацию и авторизацию пользователей, управление валютными кошельками, покупку и продажу валют, оценку портфеля и получение валютных курсов.

Пользовательские данные, портфели и курсы сохраняются в JSON-файлах.

## Используемые технологии

- **Python 3.12+** — основной язык программирования.
- **uv** — управление зависимостями и сборка пакета.
- **PrettyTable** — табличное представление данных в CLI.
- **Ruff** — проверка и форматирование кода.
- **Git** — контроль версий.

## Установка

Для работы необходимы Python 3.12 или новее и `uv`.

Установка зависимостей:

```bash
make install
```

Альтернативный способ:

```bash
uv sync
```

## Запуск

```bash
make run
```

Альтернативный способ:

```bash
uv run wallet
```

После запуска открывается интерактивный консольный интерфейс.

## Доступные команды

| Команда | Назначение |
|---|---|
| `register` | Регистрация пользователя |
| `login` | Авторизация пользователя |
| `show-portfolio` | Просмотр балансов и стоимости портфеля |
| `buy` | Покупка виртуальной валюты |
| `sell` | Продажа виртуальной валюты |
| `get-rate` | Получение прямого и обратного валютных курсов |
| `help` | Справка |
| `exit` | Завершение приложения |

Пример работы:

```text
register --username alice --password 1234
login --username alice --password 1234

buy --currency BTC --amount 0.05
show-portfolio
show-portfolio --base EUR

sell --currency BTC --amount 0.01

get-rate --from BTC --to USD
get-rate --from EUR --to RUB

exit
```

Команды `buy`, `sell` и `show-portfolio` требуют авторизации. Команда `get-rate` доступна без входа.

Текущий пользователь хранится только на уровне CLI. Повторная авторизация переключает активного пользователя.

## Модель торговли

Используется упрощённая модель симуляции торговли:

- После регистрации создаётся пустой портфель.
- `buy` увеличивает баланс выбранной валюты и при необходимости создаёт новый кошелёк.
- `sell` уменьшает баланс выбранной валюты.
- Продажа невозможна при недостатке средств.
- Покупка не списывает USD, а продажа не начисляет USD.
- Курсы служат для оценки операций и стоимости портфеля.

Начальный баланс, пополнение и обязательное наличие USD для покупки не предусмотрены.

Баланс одного пользователя не влияет на портфели других пользователей.

## Валюты и объектная модель

В `core/currencies.py` реализована иерархия валют:

- `Currency` — абстрактный базовый класс.
- `FiatCurrency` — фиатная валюта с указанием страны-эмитента.
- `CryptoCurrency` — криптовалюта с алгоритмом и рыночной капитализацией.

Поддерживаются валюты:

- `USD` — доллар США;
- `EUR` — евро;
- `RUB` — российский рубль;
- `BTC` — Bitcoin;
- `ETH` — Ethereum.

Валюты хранятся в едином реестре `CURRENCY_REGISTRY`. Функция `get_currency()` проверяет существование валюты и возвращает соответствующий объект.

Классы `User`, `Wallet` и `Portfolio` реализованы в `core/models.py`. Модели не обращаются к JSON-хранилищу самостоятельно: необходимые данные передаются через бизнес-логику.

## Курсы валют

Котировки хранятся в `data/rates.json` относительно USD:

- `BTC_USD`;
- `ETH_USD`;
- `EUR_USD`;
- `RUB_USD`.

Стоимость одной единицы USD принимается равной 1 USD.

Кросс-курсы рассчитываются через USD:

```text
Курс A→B = (стоимость A в USD) / (стоимость B в USD)
```

Команда `get-rate` показывает прямой и обратный курсы без промежуточного округления.

На текущем этапе используется **фиксированный снимок котировок от 2026-11-05**. Подключение внешнего API предусмотрено следующим этапом разработки.

Курсы кэшируются в JSON. Срок действия кэша (TTL) задаётся в настройках; по умолчанию — 300 секунд.

Для записей используются метаданные:

- `source` — источник значения;
- `snapshot_date` — дата исходного снимка котировок;
- `updated_at` — время последнего получения значения от источника;
- `saved_at` — время сохранения в кэше.

Истечение TTL приводит к повторному получению значения из текущего источника-заглушки, а не к обновлению рыночных данных в реальном времени.

## Хранение данных и настройки

В `infra/settings.py` реализован `SettingsLoader` с использованием паттерна Singleton.

Настройки считываются из секции `[tool.valutatrade]` файла `pyproject.toml`.

Основные параметры:

| Параметр | Назначение |
|---|---|
| `data_dir` | Каталог JSON-хранилища |
| `users_file` | Файл пользователей |
| `portfolios_file` | Файл портфелей |
| `rates_file` | Файл курсов |
| `rates_ttl_seconds` | Срок действия кэша |
| `default_base_currency` | Базовая валюта |
| `log_dir` | Каталог журналов |
| `log_level` | Уровень логирования |
| `log_format` | Формат журналов |
| `log_max_bytes` | Максимальный размер файла журнала |
| `log_backup_count` | Количество резервных файлов |

В `infra/database.py` реализован Singleton `DatabaseManager`, обеспечивающий работу с JSON-файлами.

Для обновления данных используется блокировка в рамках процесса и безопасная запись через временный файл с последующей заменой целевого файла.

Каталог `data/` исключён из Git.

## Обработка ошибок

В `core/exceptions.py` определены пользовательские исключения:

- `InsufficientFundsError` — недостаточно средств для продажи;
- `CurrencyNotFoundError` — неизвестная валюта;
- `ApiRequestError` — ошибка получения котировок от источника.

CLI перехватывает эти исключения и выводит понятные сообщения без завершения приложения.

При неизвестной валюте показывается список поддерживаемых кодов.

## Логирование

В `logging_config.py` настраивается журнал действий приложения.

Операции покупки и продажи логируются через декоратор `@log_action` из `decorators.py`.

Журнал содержит применимые сведения:

- тип операции `BUY` или `SELL`;
- идентификатор пользователя и параметры операции;
- валюту и сумму;
- курс и базовую валюту, если они известны;
- остатки до и после успешной операции;
- результат `OK` или `ERROR`;
- тип и сообщение исключения при ошибке.

Временные метки формируются в UTC.

Журнал по умолчанию сохраняется в `logs/actions.log`. Используется `RotatingFileHandler` с ограничением размера файла и хранением резервных копий.

Пароли в журнал операций не записываются. Каталог `logs/` исключён из Git.
