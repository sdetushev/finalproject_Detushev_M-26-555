# ValutaTrade Hub — валютный кошелёк

Консольное приложение на Python для симуляции торговли валютами, управления виртуальными кошельками и отслеживания актуальных валютных курсов.

Приложение позволяет регистрировать пользователей, управлять валютным портфелем, покупать и продавать виртуальные валюты, рассчитывать стоимость активов и получать курсы из внешних API.

Для работы с рыночными данными реализован отдельный **Parser Service**, который получает котировки от CoinGecko и ExchangeRate-API, сохраняет их в JSON и передаёт Core Service через локальный кэш.

## Используемые технологии

- **Python 3.12+** — основной язык программирования.
- **uv** — управление зависимостями, виртуальным окружением и сборкой пакета.
- **Requests** — HTTP-запросы к внешним API.
- **PrettyTable** — отображение таблиц в консоли.
- **Ruff** — проверка и форматирование Python-кода.
- **Git** — контроль версий.
- **JSON** — хранение пользователей, портфелей и валютных котировок.
- **TOML** — конфигурация приложения в `pyproject.toml`.
- **logging** — журналирование операций и ошибок.

## 2. Настройка API-ключей

Parser Service использует два внешних источника:

| Источник | Назначение | Отслеживаемые валюты |
|---|---|---|
| CoinGecko | Курсы криптовалют | BTC, ETH |
| ExchangeRate-API | Курсы фиатных валют | EUR, RUB |

Все полученные котировки приводятся к USD.

### Получение ключей

**ExchangeRate-API**

1. Перейдите на https://www.exchangerate-api.com/.
2. Зарегистрируйте бесплатный аккаунт.
3. Получите персональный API-ключ в личном кабинете.

**CoinGecko**

1. Перейдите на https://www.coingecko.com/en/api.
2. Зарегистрируйтесь и получите Demo API-ключ.
3. Сохраните ключ для настройки приложения.

Клиент CoinGecko поддерживает работу без ключа, если используемый API допускает такой доступ. Для более стабильной работы рекомендуется Demo API-ключ.

### Создание файла .env

В корне проекта находится файл `.env.example` с названиями необходимых переменных окружения:

```dotenv
EXCHANGERATE_API_KEY=
COINGECKO_API_KEY=
```

Создайте его локальную копию:

```bash
cp .env.example .env
```

Откройте `.env` и добавьте собственные API-ключи:

```dotenv
EXCHANGERATE_API_KEY=your_exchangerate_api_key
COINGECKO_API_KEY=your_coingecko_api_key
```

Замените примеры своими ключами. Пробелы вокруг `=` не нужны.

При запуске через `uv run --env-file .env` переменные окружения загружаются автоматически. `ParserConfig` получает их через `os.getenv()`.

## 3. Запуск приложения

### Запуск с API-ключами

```bash
uv run --env-file .env wallet
```

После запуска открывается интерактивный консольный интерфейс.

Для запуска без явного указания `.env` можно предварительно установить переменную окружения:

```bash
export UV_ENV_FILE=.env
```

После этого доступны обычные команды:

```bash
make run
```

или:

```bash
uv run wallet
```

Если переменные окружения не настроены, функции, не требующие внешних API, остаются доступными. Однако обновление курсов через ExchangeRate-API требует действующего ключа.

### Первый запуск

Рекомендуемый порядок действий:

1. Установить зависимости через `uv sync`.
2. Создать `.env` и указать API-ключи.
3. Запустить приложение.
4. Выполнить `update-rates`, чтобы загрузить актуальные котировки.
5. Зарегистрировать пользователя и авторизоваться.
6. Использовать команды управления портфелем.

## 4. Доступные команды

| Команда | Назначение |
|---|---|
| `register` | Регистрация пользователя |
| `login` | Авторизация пользователя |
| `show-portfolio` | Просмотр балансов и стоимости портфеля |
| `buy` | Покупка виртуальной валюты |
| `sell` | Продажа виртуальной валюты |
| `get-rate` | Получение прямого и обратного валютных курсов |
| `update-rates` | Обновление котировок из внешних API |
| `show-rates` | Просмотр локального кэша валютных курсов |
| `help` | Справка по командам |
| `exit` | Завершение приложения |

### Пример работы

```text
update-rates

register --username alice --password 1234
login --username alice --password 1234

buy --currency BTC --amount 0.05
buy --currency EUR --amount 100

show-portfolio
show-portfolio --base EUR

sell --currency BTC --amount 0.01

get-rate --from BTC --to USD
get-rate --from EUR --to RUB

show-rates
show-rates --currency BTC
show-rates --top 2
show-rates --top 2 --base EUR

exit
```

Команды `buy`, `sell` и `show-portfolio` требуют авторизации.

Команды `get-rate`, `update-rates` и `show-rates` доступны без входа в аккаунт.

Текущий пользователь хранится на уровне CLI. Повторная авторизация переключает активного пользователя.

## 5. Регистрация и управление портфелем

### Пользователи

Команда `register` создаёт нового пользователя и пустой виртуальный портфель.

Команда `login` выполняет авторизацию существующего пользователя.

### Валютные кошельки

Каждый пользователь имеет собственный портфель, который содержит кошельки с балансами разных валют.

Команды:

```text
buy --currency BTC --amount 0.05
sell --currency BTC --amount 0.01
```

### Модель торговли

В проекте используется упрощённая учебная модель:

- После регистрации создаётся пустой портфель.
- `buy` увеличивает баланс выбранной валюты.
- При первой покупке создаётся кошелёк для соответствующей валюты.
- `sell` уменьшает баланс выбранной валюты.
- Продажа невозможна при недостатке средств.
- Покупка не списывает USD с другого кошелька.
- Продажа не начисляет USD на другой кошелёк.
- Курсы используются для оценки операций и стоимости портфеля.

Начальный баланс и механизмы пополнения не предусмотрены.

Баланс одного пользователя не влияет на портфели других пользователей.

### Оценка портфеля

Команда:

```text
show-portfolio
```

показывает балансы и стоимость активов.

Для изменения валюты отображения:

```text
show-portfolio --base EUR
```

По умолчанию стоимость рассчитывается в валюте, заданной параметром `default_base_currency` в `pyproject.toml`.

Внутренний расчёт выполняется через долларовые котировки.

## 6. Валюты и объектная модель

В `core/currencies.py` реализована иерархия валют:

- `Currency` — абстрактный базовый класс.
- `FiatCurrency` — фиатная валюта с указанием страны эмитента.
- `CryptoCurrency` — криптовалюта с характеристиками алгоритма и рыночной капитализации.

Поддерживаются валюты:

| Код | Валюта | Тип |
|---|---|---|
| USD | Доллар США | Фиатная |
| EUR | Евро | Фиатная |
| RUB | Российский рубль | Фиатная |
| BTC | Bitcoin | Криптовалюта |
| ETH | Ethereum | Криптовалюта |

Валюты объединены в реестре `CURRENCY_REGISTRY`.

Функция `get_currency()` проверяет код и возвращает соответствующий объект. Для неизвестного кода предусмотрено исключение `CurrencyNotFoundError`.

В `core/models.py` реализованы классы:

- `User` — пользователь;
- `Wallet` — валютный кошелёк;
- `Portfolio` — набор кошельков пользователя.

## 7. Получение и расчёт валютных курсов

### Источники данных

Котировки поступают из двух API:

**CoinGecko**

Используется endpoint:

```text
https://api.coingecko.com/api/v3/simple/price
```

Запрашиваются криптовалюты по их идентификаторам:

```text
bitcoin
ethereum
```

Для сопоставления тикеров с идентификаторами используется `CRYPTO_ID_MAP`.

**ExchangeRate-API**

Используется endpoint вида:

```text
https://v6.exchangerate-api.com/v6/<API_KEY>/latest/USD
```

Из ответа извлекаются курсы фиатных валют.

Поскольку ExchangeRate-API возвращает количество единиц иностранной валюты за 1 USD, для получения стоимости одной единицы иностранной валюты в USD применяется обратное значение.

Например, если:

```text
1 USD = 0.90 EUR
```

то:

```text
1 EUR = 1 / 0.90 USD
```

### Расчёт кросс-курсов

Для расчёта курса валюты A относительно B используется формула:

```text
Курс A→B = (стоимость A в USD) / (стоимость B в USD)
```

Например, курс BTC/EUR рассчитывается через BTC/USD и EUR/USD.

Команда:

```text
get-rate --from BTC --to EUR
```

показывает прямой и обратный курсы.

Промежуточное округление в расчётах не выполняется.

## 8. Parser Service

Parser Service отвечает за получение, нормализацию, проверку, сохранение и периодическое обновление валютных котировок.

Сервис расположен в каталоге:

```text
valutatrade_hub/parser_service/
```

### Основные компоненты

| Модуль | Назначение |
|---|---|
| `config.py` | Настройки источников, валют, API-ключей, таймаута и путей |
| `api_clients.py` | Клиенты CoinGecko и ExchangeRate-API |
| `storage.py` | Работа с текущим кэшем и историей курсов |
| `updater.py` | Координация получения и сохранения котировок |
| `scheduler.py` | Периодическое обновление курсов |

### API-клиенты

В `api_clients.py` определены:

- `BaseApiClient` — абстрактный базовый класс;
- `CoinGeckoClient` — получение курсов криптовалют;
- `ExchangeRateApiClient` — получение курсов фиатных валют.

Оба клиента реализуют метод:

```python
fetch_rates() -> dict[str, float]
```

API-клиенты выполняют HTTP-запросы через `requests`, проверяют ответы, преобразуют значения в единый формат и обрабатывают ошибки.

Для HTTP-запросов предусмотрены таймаут, обработка сетевых исключений, ошибочных HTTP-статусов и некорректных данных.

### Обновление котировок

Класс `RatesUpdater` последовательно обращается к API-клиентам.

Общий процесс:

```text
CoinGecko ───────────────┐
                         ├── RatesUpdater
ExchangeRate-API ────────┘        |
                                  v
                             RatesStorage
                                  |
                    +-------------+-------------+
                    |                           |
                    v                           v
              rates.json              exchange_rates.json
                    |
                    v
               Core Service
                    |
                    v
                   CLI
```

Parser Service запрашивает данные из внешних API, а Core Service работает с локальным кэшем и не делает отдельный HTTP-запрос при каждой пользовательской операции.

## 9. Ручное обновление курсов

Для немедленного обновления всех отслеживаемых валют используется:

```text
update-rates
```

Можно выбрать конкретный источник:

```text
update-rates --source coingecko
```

или:

```text
update-rates --source exchangerate
```

Команда выводит:

- источник данных;
- количество полученных котировок;
- количество обновлённых записей кэша;
- итоговый статус;
- время последнего обновления;
- сообщения об ошибках при их наличии.

Количество полученных курсов может отличаться от числа обновлённых записей, если API повторно вернул уже сохранённые измерения.

Для работы этой команды необходим доступ к интернету и корректная настройка API-ключей.

## 10. Просмотр сохранённых курсов

Команда `show-rates` работает с локальным кэшем, не отправляя запросов к внешним API.

### Все курсы

```text
show-rates
```

### Конкретная валюта

```text
show-rates --currency BTC
```

### Пересчёт относительно другой валюты

```text
show-rates --base EUR
```

### Топ криптовалют

```text
show-rates --top 2
```

Параметр `--top N` выбирает N самых дорогих криптовалют по цене одной единицы в USD.

### Комбинация параметров

```text
show-rates --top 2 --base EUR
```

Фильтры можно использовать совместно.

Для отображения применяется PrettyTable.

Таблица содержит:

- валютную пару;
- курс;
- источник;
- время обновления исходных данных в UTC;
- статус актуальности.

Если котировка устарела, отображается предупреждение с предложением выполнить `update-rates`.

## 11. TTL и актуальность котировок

TTL (Time To Live) определяет, сколько времени полученная котировка считается актуальной.

Значение задаётся в `pyproject.toml`:

```toml
rates_ttl_seconds = 3900
```

Текущая настройка составляет 3900 секунд, то есть 65 минут.

Для проверки свежести применяется `saved_at` — время последнего успешного получения котировки.

`updated_at` сохраняет время исходных данных API.

При расчёте кросс-курса проверяется актуальность обеих необходимых валют относительно USD.

Если нужная котировка отсутствует или устарела, пользователь получает сообщение об ошибке и предложение выполнить `update-rates`.

Команда `show-rates` может показывать устаревшие значения с соответствующим предупреждением.

## 12. Автоматическое обновление курсов

В `parser_service/scheduler.py` реализован класс `RatesScheduler`.

Планировщик запускает `RatesUpdater` через заданные интервалы времени.

### Запуск

Из корня проекта выполните:

```bash
uv run --env-file .env python -m valutatrade_hub.parser_service.scheduler
```

После запуска планировщик сразу выполняет первое обновление, затем ожидает установленный интервал.

### Настройка интервала

В `pyproject.toml`:

```toml
rates_update_interval_seconds = 3600
```

Значение 3600 означает обновление один раз в час после завершения предыдущего цикла.

### Обработка ошибок

При временной недоступности API планировщик:

- фиксирует ошибку в журнале;
- сохраняет ранее полученные курсы;
- продолжает работу в следующих циклах.

Критические ошибки конфигурации и файлового хранилища не скрываются.

### Остановка

Для остановки нажмите:

```text
Ctrl+C
```

Планировщик корректно завершит выполнение.

Планировщик работает отдельным процессом только во время его запуска. Он не устанавливается автоматически как системная служба.

## 13. Хранение данных и настройки

В `infra/settings.py` реализован `SettingsLoader` с использованием паттерна Singleton.

Настройки приложения считываются из раздела `[tool.valutatrade]` файла `pyproject.toml`.

Основные параметры:

| Параметр | Назначение |
|---|---|
| `data_dir` | Каталог JSON-хранилища |
| `users_file` | Файл пользователей |
| `portfolios_file` | Файл портфелей |
| `rates_file` | Файл текущего кэша |
| `exchange_rates_file` | Файл истории валютных курсов |
| `rates_ttl_seconds` | Срок актуальности котировок |
| `rates_update_interval_seconds` | Интервал работы планировщика |
| `default_base_currency` | Валюта отображения портфеля по умолчанию |
| `log_dir` | Каталог журналов |
| `log_level` | Уровень логирования |
| `log_format` | Формат логов приложения |
| `log_max_bytes` | Максимальный размер файла журнала |
| `log_backup_count` | Количество резервных файлов |

Класс `ParserConfig` содержит конфигурацию внешних API, списки отслеживаемых валют, таймаут HTTP-запросов и пути к файлам.

В `infra/database.py` реализован Singleton `DatabaseManager`, обеспечивающий чтение, запись и обновление JSON-данных приложения.

## 14. Логирование

### Журнал пользовательских операций
